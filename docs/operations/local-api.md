# Initial local API adapter

`create_app` provides read-only authenticated health, paginated event replay, and WebSocket event replay. It is an application component, not a daemon executable. The daemon must own the database lock and supply a nonblocking or short-running `read_events(after, limit)` callback on the ASGI event loop. A suitable callback delegates to `synapse.persistence.event_store.read_events` using a connection valid on that thread. Errors from the reader are not hidden or converted to empty event lists.

This slice has one operator identity with access to **all** events. The caller must generate a cryptographically random, unique ASCII bearer secret of at least 32 characters, keep it in protected memory and deliver it securely to trusted clients. Length validation does not establish entropy. Do not put the secret in URLs or logs. The app accepts one Authorization header only and rejects Origin headers; WebSocket clients authenticate with the header as well. No per-run or agent authorization exists yet, so do not expose this endpoint to agents.

Serve only on a user-private Unix socket in a private directory. The ASGI server must accurately populate `scope["client"]`: this adapter rejects a non-null client address to fail closed for TCP. This check relies on the server's ASGI scope and does not replace socket permissions. Configure the server and process umask so unauthorized users cannot connect. The adapter does not create a socket, manage secrets, provide a ready daemon, or support authenticated loopback TCP. OpenAPI is also authenticated. The real Unix-socket test uses Uvicorn; other ASGI servers must be verified before use.

Events use global sequence cursors. Fetch a snapshot then subscribe with its last sequence; reconnect using the last processed sequence and deduplicate by event ID. Sequences can have gaps. The stream polls in bounded pages and rejects client messages; a slow reader applies transport backpressure. Event retention and gap detection are not implemented. Run and approval queries are read-only; workflow publication and run queueing are available to the operator. The operator can start and cancel the fixed synthetic mock fixture; agent-scoped access and message sending are not exposed. Approval decisions are accepted only at `POST /api/v1/approvals/{approval_id}/decision` with the human approver token. The CLI and desktop currently provide partial operator views.

## Running the initial daemon

Install the project with its runtime dependencies, create a user-owned directory with mode `0700`, and run `agentd --state-dir /path/to/private-dir --migrations /path/to/synapse/migrations`. The daemon holds its database ownership lock from before migration until after the server stops. It creates a random operator token in `operator.token` with mode `0600`, keeps it across restarts, and exposes `agentd.sock` with mode `0600`. Read the token only as an authorized local operator; send it as a bearer header. The daemon disables HTTP access logs. It does not manage provider subscription credentials.

SIGINT and SIGTERM request graceful server shutdown; the daemon closes the database, releases the lock and removes its own socket path. A hard kill or crash can leave the socket file. While holding the daemon lock, startup reclaims `agentd.sock` (and `mock-mcp.sock`) only if it is a user-owned socket that refuses connections; a live listener, regular file, symlink, foreign owner or ambiguous probe is never replaced and startup fails. Limit: a process that bound that private path but has not yet called listen() is indistinguishable from a crash remnant. A crash while initially creating the token may leave an invalid file; startup fails closed rather than silently replacing it. Back up and protect the state directory and token together. Reclaim opens the socket's parent directory once, verifies it (a directory owned by the user or root, not writable by others unless sticky) and performs the lstat, connect probe (via `/proc/self/fd` on Linux) and unlink relative to that descriptor, rechecking the inode before unlinking, so a swapped parent directory or symlink cannot redirect them; a final lstat-to-unlink window against a same-user attacker remains, so a private directory is still a required trust boundary against path replacement. This daemon can run the fixed synthetic mock fixture. Interrupted mock work is reconciled conservatively; automatic resume is not available. Real Claude CLI agent runs exist only when the operator passes `--claude-cli-config` (see Real agent runs below).

The current operator token authenticates a holder, not a distinct human. Processes running as the same OS user may be able to read it. Do not use this token as proof of human approval or expose privileged operator endpoints to agent processes; distinct human authorization and requester separation are required before approval decisions or privileged execution are enabled.

A refused Unix-socket connection is not proof that a socket is stale: a live process can bind the path before it calls `listen`. The database lock coordinates Synapse daemons but does not exclude unrelated processes binding the same socket. Automatic unlinking based on a failed connect or an inode check can remove a live or replaced endpoint; startup therefore continues to refuse an existing path. Operator reconciliation must verify ownership independently before cleanup.

A trusted supervisor can retain a private listening Unix socket at `agentd.sock` and pass its inherited descriptor using `agentd --state-dir DIR --migrations DIR --socket-fd N`. The descriptor must identify a listening Unix stream socket bound to that exact path; the path must be a private user-owned socket in the private state directory. The daemon duplicates and closes only its copy, never unlinks the supervisor-owned path, and validates before database recovery. The supervisor retains ownership across daemon crashes and must restart the daemon; without one the original stale-socket procedure remains necessary. For systemd socket activation, a single listener may be passed as descriptor 3 with `--socket-fd 3`; configure private socket and directory permissions and restart behavior separately. This feature installs or enables no service. See [ADR 013](../adr/013-supervisor-owned-socket.md) for trust and delivery limitations.

## Real agent runs

`POST /api/v1/agent-runs` (201 new, 200 replay), `GET /api/v1/runs/{id}/agent` and `POST /api/v1/runs/{id}/agent-cancel` start, inspect and cancel a real Claude CLI run in a git worktree. They need the operator config described in [agent-runs](agent-runs.md); otherwise start answers 503.

## Listing runs

`GET /api/v1/runs` (operator Bearer token) lists runs newest first, ordered by `(created_at, id)` descending. Query: `limit` (1-200, default 50), `state` (one of `created`, `queued`, `running`, `awaiting_approval`, `paused`, `recovering`, `succeeded`, `failed`, `cancelled`) and `cursor` (opaque; pass the previous `next_cursor`). The response is `{"runs": [...], "next_cursor": string|null}`; `next_cursor` is null on the last page. Each run has `id`, `workflow_id`, `workflow_version`, `state`, `state_version`, `created_at`, `updated_at`, `task_counts` (task state to count) and `pending_approvals` (approval requests in `requested`). A page, its task counts and approval counts are read in one SQLite snapshot. Invalid `limit`, `state` or `cursor` return 422. `agentctl runs [--state S] [--limit N] [--cursor C] [--json]` prints a compact table or the raw response.

## Run usage

`GET /api/v1/runs/{run_id}/usage` (operator Bearer token) returns the provider-reported usage ledger for one run in a single SQLite snapshot: `run_id`, `attempts_total`, `attempts_with_usage`, `observations` (one page of recorded observations), `totals`, per-field `coverage` and `next_cursor`. `totals`, `coverage`, `attempts_total` and `attempts_with_usage` always cover the whole run; only `observations` is paged, ordered by `(observed_at, id)`, with query `limit` (1-500, default 200) and `cursor` (the previous `next_cursor`, null on the last page). An invalid or foreign cursor or an out-of-range limit returns 422. A field nobody reported is `null`, never `0`; a total is a lower bound when `coverage.<field>.known < attempts`. An unknown run returns 404. `agentctl usage RUN_ID [--limit N] [--cursor C]` prints the raw page; when more pages exist it also prints the `--cursor` for the next page on stderr. For an unknown run it prints nothing on stdout, reports the 404 on stderr and exits 1. Field semantics are in [usage ledger](usage-ledger.md).
