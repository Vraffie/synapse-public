# Local operator CLI

With the daemon running and the package installed, use `agentctl --state-dir /path/to/private/state health` for health and `agentctl --state-dir /path/to/private/state events --after 0 --limit 100` to fetch a JSON event page. Save the highest sequence processed and pass it as `--after` to continue; sequence gaps are normal. Event retention and gap detection are not yet implemented.

The CLI reads the daemon-generated `operator.token` from the private state directory and connects only to `agentd.sock`. It requires a user-owned private directory, a user-owned regular token file with no group/other permissions and one hard link, and a private user-owned socket; symlink token files are rejected. Keep the state directory private to protect against replacement races. Token values and server error bodies are not printed. Responses are limited to 16 MiB; use smaller event pages if necessary. Treat output as sensitive because events may contain private data.

Read a run snapshot with `agentctl --state-dir /path/to/private/state run RUN_ID` and its task details with `agentctl --state-dir /path/to/private/state tasks RUN_ID [--limit N] [--cursor C]` (one page of at most `--limit` tasks, 1-500, default 200; when more exist the next `--cursor` value is printed on stderr). The run ID must be a single path segment. List approval records with `agentctl --state-dir /path/to/private/state approvals --after LAST_ID --limit 100`; use the last ID as the next cursor. Concurrent inserts before the cursor require a fresh scan.

List a run's threads with `agentctl --state-dir /path/to/private/state threads RUN_ID --after 0 --limit 100`; inspect one thread with `agentctl --state-dir /path/to/private/state messages RUN_ID THREAD_ID --after 0 --limit 100`. The last returned row's `cursor` is the next `--after` value. Both IDs must be single path segments. Cursors are local SQLite row IDs, not event sequences; thread deletion and reinsertion can reuse IDs, so refresh from zero to detect changes behind the cursor. Message payloads can contain sensitive information.

The query commands above are read-only. General run lifecycle controls, message sending, interactive streaming and per-agent authorization are not yet implemented. Approval decisions use `approver-init` and `approval-decide` with the separate approver token, not the operator token.

Publish a workflow JSON file with `agentctl --state-dir /path/to/private/state publish-workflow workflow.json --idempotency-key publish-1 --correlation-id trace-1`. Input must be a regular file (no symlink) no larger than 1 MiB; the daemon validates its JSON and DAG. Queue a run with `agentctl --state-dir /path/to/private/state queue-run WORKFLOW_ID VERSION --idempotency-key run-1 --correlation-id trace-2`. Both keys are required; retain and reuse the same idempotency key when retrying the same command to avoid duplicates. Reusing a key with a different request fails. A queued run does not start a worker. These operator commands do not grant approval or deployment authority; bearer-token access must remain isolated from workers.

Start, inspect and cancel REAL agent runs with `agent-start` (prompt from `--prompt-file FILE|-`, never argv), `agent-show RUN` and `agent-cancel RUN`; see [agent runs](agent-runs.md). `agent-worktree-commit RUN -m MESSAGE` commits a finished run's worktree edits onto its own branch `synapse/<run>/<task>` (host-side, never your checkout, never pushed); `agent-abandon` and `agent-worktree-remove` end or clean up finished runs (also in agent-runs.md).
List agent profiles with `profiles` and set or clear an operator cooldown with `profile-cooldown PROFILE --seconds N | --clear` (audited; a cooling profile makes tasks that name it fail closed, nothing is retried or rerouted); see [agent profiles](agent-profiles.md).

Start a queued run using the daemon's fixed synthetic fixture with `agentctl --state-dir /path/to/private/state mock-start RUN_ID --idempotency-key start-1 --correlation-id trace-3`. Retain the key for retries; repeating it replays the original start response and does not relaunch work. This invokes only the server-owned mock fixture and deterministic fixture check, never a provider CLI. It does not constitute independent review of real work. See [daemon mock execution](daemon-mock.md) for crash-recovery and stale-socket limits.

Request cancellation of an actively running synthetic mock with `agentctl --state-dir /path/to/private/state mock-cancel RUN_ID --idempotency-key cancel-1 --correlation-id trace-4`. Reuse the key to retry the same request. A `cancellation_requested` response means the intent was durably accepted; it does not mean the worker has stopped. Poll `agentctl ... run RUN_ID` for the final state. This command does not cancel live provider processes. See [mock cancellation](mock-cancellation.md) for recovery and failure behavior.

To reconcile and resume a recovering fixed synthetic mock run, first inspect it with `agentctl --state-dir /path/to/private/state run RUN_ID` and `agentctl --state-dir /path/to/private/state tasks RUN_ID`. After inspecting every blocked task and unknown attempt, write the explicit evidence JSON described in [mock recovery](mock-resume.md), then run `agentctl --state-dir /path/to/private/state mock-resume RUN_ID evidence.json --idempotency-key resume-1 --correlation-id trace-4`. The CLI sends exactly the operator-authored JSON; it does not infer evidence or assert safety on the operator's behalf. The evidence file must be regular and no larger than 1 MiB; the final path component cannot be a symlink. Keep parent directories trusted because they may contain symlinks. Keep the same key for an exact retry. This command applies only to the built-in in-process synthetic fixture and is not human approval or authorization for live providers, external effects or deployment.

Read a run's provider-reported token and cost ledger with `agentctl --state-dir /path/to/private/state usage RUN_ID [--limit N] [--cursor C]`; totals and coverage cover the whole run, the observation list is one page and the next `--cursor` is printed on stderr when more exist. Unknown values are `null` (never `0`) and `coverage` shows how many attempts reported each field, so a total with `known < attempts` is only a lower bound; cost is an API-equivalent estimate, not a charge. See [usage ledger](usage-ledger.md) and [local API](local-api.md#run-usage).

Read a run's analytics (measured, estimated and unknown numbers, each with `known`/`of`/`lower_bound` coverage) with `agentctl --state-dir /path/to/private/state analytics RUN_ID [--limit N] [--cursor C]` (tasks per page 1-200, default 50). Run-level totals cover the whole run; when more tasks exist the next `--cursor` value is printed on stderr. Unknown values are `null`, never `0`, and estimates are never merged into measured totals. See [analytics views](analytics-views.md) and [local API](local-api.md#run-analytics).
