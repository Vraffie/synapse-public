# MCP stdio bridge (integration component)

The optional `mcp` extra supplies the official MCP Python SDK. The stdio subprocess `python -m synapse.mcp_gateway` offers `send_message`, `get_inbox`, `read_delivery` and `ack_delivery`. The trusted launcher must inject `SYNAPSE_MCP_SOCKET` (an absolute path) and `SYNAPSE_MCP_CREDENTIAL` (an ephemeral Synapse agent session bearer) into the subprocess environment. These are Synapse session credentials, not provider subscription credentials. The subprocess removes these values from its environment on startup, accesses no SQLite, and passes requests to the daemon-owned gateway. It checks that the socket and its parent are private and user-owned. It returns generic errors without logging credentials. The selected session identity is always derived by the daemon, not from MCP tool arguments.

The daemon can host `private_ipc_server(path, gateway)` on its SQLite-owning event loop while holding the daemon database lock. The parent directory must already be private and user-owned; existing filesystem entries are never replaced. The server caps concurrent clients, input bytes, response bytes, and read/write time. It authenticates each request through the in-process gateway, preserves its authorization and revocation rules, and deletes only the socket inode it created. Shutdown cancels outstanding IPC handlers. The socket directory remains part of the trust boundary; same-user agents with process-memory or environment access may steal session credentials. MCP clients must receive only their own session credential and trusted launch configuration.

`agentd --enable-mock-mcp-ipc` starts this private IPC listener on the same event loop and database-owning thread as the daemon. It is disabled by default and starts with an empty session authority, so all requests are denied. The daemon does not issue agent credentials or connect mock workers to the listener. The flag is an integration hook, not working agent communication. Existing socket paths block startup and are preserved; clean shutdown removes only the socket created by this process. Worker launch, session issuance, delivery grant provisioning and agent MCP configuration are not wired. No installed Claude/Codex version or profile capabilities have been verified. Do not claim live MCP communication until those integrations and independent security review are complete. The proxy limits each newline-delimited stdio message to 131072 bytes and nesting to 64 levels before UTF-8 decoding and SDK JSON parsing; over-limit or incomplete input closes the proxy. The launcher must still impose process memory and CPU ceilings. Fallback communication and session recovery remain separate work.

`get_inbox` requires an `idempotency_key`. Reuse the same key to recover a lost response while the returned leases remain live; use a new key for a new poll. Replaying a completed, expired or superseded lease fails instead of returning a stale token. The key is scoped to the current authenticated session, not to a future replacement session.

The current same-user process model cannot protect per-agent session secrets from other processes with equivalent memory or environment inspection privileges. No session is issued through this daemon hook until an independently reviewed OS isolation and secure delivery mechanism is available. Do not enable real provider execution through this endpoint.

The bounded reader uses Unix event-loop file-descriptor readiness and expects the MCP client to supply stdin as a pipe or socket. On platforms where the event loop cannot monitor the supplied descriptor (including Linux regular-file redirection), it fails closed; it does not fall back to an unbounded read. This transport remains Linux/Unix-specific.
