# Agent session authority

The in-memory `SessionAuthority` issues randomly generated per-session bearer credentials and derives a fixed agent instance, run, and exact action/resource grants from the credential. Trusted daemon code alone must issue and revoke them. Revocation invalidates the identity and grants; restart invalidates all sessions. Session and grant counts are bounded. Secrets are redacted from credential representations and must not be logged or placed in URLs.

No transport, MCP gateway, identity-to-database provisioning, expiry, or process isolation is provided by this component. A trusted transport must authenticate the secret itself, take the principal from the returned identity rather than request data, and call the scoped service with that principal. Serialize revocation with any operation that must not complete after revocation; a check and a later write are not one atomic operation. Same-user processes able to inspect the daemon's memory or the worker's environment can steal a bearer credential; OS isolation and secure delivery remain necessary. Issuers must authorize all grants and their run/resource scope before issuance. Existing messaging service checks database run membership and resource scope separately.
