# Bidirectional MCP message integration test

`tests/test_mcp_bidirectional_integration.py` runs two distinct simulated agent instances through actual MCP SDK clients and separate stdio proxy subprocesses connected to a protected in-process daemon-side IPC gateway. The author sends a review request; the reviewer claims, reads and acknowledges it, then sends a causally linked finding. The test closes the IPC gateway and daemon-owned database, reopens both with a fresh session authority, rejects the old credential, and has the author claim, read and acknowledge the durable reply. It checks send and ACK replay within a session, delivery state, event/outbox counts, and exact delivery grant provisioning.

The harness provisions agents, sessions, artifact metadata and delivery grants directly as trusted daemon code. These are simulated agents, not invocations of the mock workflow engine or real CLI workers. It does not start `agentd` or prove automatic session provisioning, connection of active workflow agents, lease-expiry redelivery, agent correction after the finding, or independent review of code. Session secrets are ephemeral and old secrets fail after restart; idempotency responses tied to a session principal are not claimed to survive session reissuance.
