# Mock restart reconciliation primitive

`recover_mock_run` is an explicit daemon-owned recovery operation, not startup wiring. Invoke it only after acquiring the exclusive database ownership lock and independently establishing that no previous worker can survive or produce effects. Its `no_workers_survive=True` argument is an attestation by trusted daemon code, not fencing or proof; never infer it from a stale PID or use it for live providers. It rejects missing/non-mock profiles and inconsistent unresolved task states before changing anything. It does not contact providers or resume work.

In one transaction, created/starting/running attempts become unknown and affected assigned, running, verifying, ready or dependency-waiting tasks become blocked; already blocked tasks and already unknown attempts remain unchanged. The state-machine's assigned-to-blocked edge allows the daemon to stop a claimed task safely when startup was interrupted. This is consistent with the architecture's blocked task state and does not change its requirements. A verifying task is blocked even if its worker finished: a verifier may have been interrupted, and no completion is inferred. Every change produces an event and outbox entry. Failure rolls back the entire run's reconciliation; repeating it is idempotent. The run state is not automatically changed. Unknown outcomes remain non-retryable until a separate authorized reconciliation resolves them. Previously completed tasks remain untouched.

This primitive does not implement worker fencing, external-process reconciliation, persistent scenario definitions, automatic restart/resumption, or daemon startup integration. The mock-only assumption applies to all attempts of affected tasks, including terminal ones. A terminal run containing unresolved work fails closed for investigation.
