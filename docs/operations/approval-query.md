# Approval query

The authenticated local operator can read `GET /api/v1/approvals?after=<id>&limit=<1..1000>`. Results include operation, target, candidate hash, policy version, lifecycle state, expiry and decision details. Results are ordered by ID; use the last ID as the next cursor. Concurrent inserts before that cursor require a fresh scan. This endpoint gives the operator access to all approvals and must not be exposed to agents or untrusted clients.

There is deliberately no decision endpoint. The current operator bearer token proves possession of a private same-user file, not that the caller is a distinct human; a worker with the same OS identity could potentially access it. The approval schema also does not record a requester identity against which to check self-approval. Safe implementation requires a separately protected human authentication channel, worker isolation from operator credentials, durable requester identity, authorization and audit checks, and revalidation of candidate, policy, expiry and target before any external action. UI confirmation alone or a caller-supplied human label does not establish these properties. No deployment or execution capability is enabled.
