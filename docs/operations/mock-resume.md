# Explicit recovery of fixed mock runs

After an interrupted managed `fixed-v1` run is marked recovering, a trusted local operator may explicitly reconcile and resume it through `POST /api/v1/runs/{run_id}/mock-resume`. This endpoint is restricted to the private operator transport. It does not authenticate a distinct human and must never authorize deployment, live providers, arbitrary mock adapters, real worker effects or agent-originated requests. The fixed fixture is synthetic and runs in the daemon process. Daemon code, not the request, establishes that its in-process worker and cancellation coroutine are stopped. A previous daemon process must have terminated and released exclusive database ownership before startup recovery.

Send an `Idempotency-Key` and `X-Correlation-ID` and JSON containing `expected_run_version`, an explicit `assertion` equal to `fixed-v1-no-external-effects`, and `tasks`: one object for every blocked task with `task_id`, `expected_version`, and its exact `unknown_attempt_id` (or null when no unresolved attempt exists). Obtain current task and attempt states from the run/task queries; `GET /api/v1/runs/{run_id}/tasks` is paged, so follow `next_cursor` until it is null (the desktop does this, at most 1000 tasks, and fails closed beyond that). The operator must inspect the evidence before making the assertion. Stale versions, omitted blocked tasks, unknown or changed attempts, non-fixture profiles, active workers, pending cancellation, another active mock run, and tasks already at the two-attempt limit fail closed. An unknown synthetic attempt is classified failed only after this explicit assertion; it is never automatically retried. Reconciliation, task/run compare-and-swap transitions, audit, events, outbox and receipt commit atomically. A new attempt receives a fresh identity and must pass verification.

An exact idempotent replay is a historical receipt and never launches another worker. If the daemon crashes after reconciliation but before scheduling, restart marks the run recovering again; inspect current state and use fresh evidence and a new key for any subsequent decision. Automatic reconciliation or resumption is not implemented. The supervisor can restart a daemon but cannot establish safety for external workers; its own hard kill can leave a child and socket. No credential or provider policy bypass is permitted.
