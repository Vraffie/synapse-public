# Optional local daemon supervisor

Run `agentd-supervisor --state-dir /path/to/private/state [--migrations DIR]` (defaults to the packaged migrations) in a trusted long-lived session or an explicitly configured service manager. It creates and retains the private listener, starts one daemon with its inherited descriptor, and restarts a child that exits nonzero after exponential backoff. Defaults allow five restarts in the supervisor lifetime, starting at 0.25 seconds and capped at 8 seconds. Configure the bounds with `--max-restarts`, `--base-delay` and `--max-delay`. To run the agent runtime under the supervisor, pass `--claude-cli-config FILE` (resolved to an absolute path) and/or `--enable-mock-mcp-ipc`; both are forwarded unchanged to every daemon child, next to `--socket-fd` and `--socket-identity`. Without them the agent runtime stays disabled. A malformed config makes the child fail before touching state and is retried only within the bounded restart budget. Reaching the restart limit exits nonzero; there is no infinite retry. A clean child exit stops the supervisor.

SIGINT or SIGTERM requests graceful child shutdown, waits up to `--shutdown-timeout` (default five seconds), then kills only that owned child if needed. Normal exit removes only the listener this supervisor created. A supervisor SIGKILL cannot be handled: its child may survive and its socket path may remain. Before restarting or removing any existing path, verify the supervisor and daemon are stopped and the socket is stale. An existing path is never replaced. No service is installed or enabled by this command, and terminal closure or logout can stop it unless an operator configures external supervision. Provider credentials are neither inspected nor changed. Daemon recovery marks ambiguous mock attempts unknown and does not automatically retry them.

## Socket ownership (security review F11)

- `agentd.sock` is bound and reclaimed only while holding an exclusive flock on `agentd.sock.lock` in the state directory (kept for the listener's lifetime, never deleted). A second supervisor (or standalone daemon) on the same state directory fails fast with `DaemonAlreadyRunning` and never reaches the stale-socket reclaim, so it cannot unlink a live socket that is between `bind` and `listen`.
- The socket is created under `umask(0o177)`, so it is never visible with a mode wider than 0600 (the chmod remains as a second step; the umask is restored right after `bind`).
- The supervisor records the socket path's `(st_dev, st_ino)` after binding and passes it to the daemon child as `--socket-identity DEV:INO`. The child refuses to start if the path is no longer that inode (a same-user process swapped in its own listener). Socket activation without this argument (systemd) keeps only the type/owner/mode/name checks; same-user processes can already read the state directory's tokens, so this is misdirection hardening, not a boundary.
- The identity check is startup-only: the child verifies it once, before serving, so a swap after startup is not detected. A child that exits because of a failed identity check (exit status 78) is not restarted by the supervisor. This is misdirection hardening only.
- The socket is bound under `os.umask`, which is process-wide; do not bind other sockets from other threads of the same process concurrently.
- Not covered: the mock MCP IPC socket (`src/synapse/mcp_gateway/ipc.py`) still uses the unlocked `reclaim_stale_socket` and takes neither the socket lock nor an identity check.
