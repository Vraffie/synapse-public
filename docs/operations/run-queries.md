# Operator run queries

The operator-only local API provides `GET /api/v1/runs/{id}` for a consistent run snapshot, task dependencies and global event cursor, and `GET /api/v1/runs/{id}/tasks` for the run's tasks with their attempts. Each response is independently read in a SQLite snapshot; the two requests need not reflect the same instant. Unknown runs return 404. Authorization is the same all-runs operator credential as other local API reads; never expose it to agents. Attempts may contain local worktree paths and session identifiers. `GET /api/v1/runs/{id}/tasks` is paged: query `limit` (1-500, default 200) and `cursor` (opaque, 1-1024 characters; pass the previous `next_cursor`). The response is `{"tasks": [...], "next_cursor": string|null}` with tasks ordered by id and each task's attempts loaded for that page only; `next_cursor` is null on the last page. A call without paging parameters returns at most the first 200 tasks, never the whole run. Pages are keyset pages (`id` after the cursor), each read in its own snapshot: a task created between pages appears later only if its id sorts after the cursor, and no task is repeated. A malformed, oversized, non-ASCII or wrong-arity cursor, or one issued for another run or for `/usage`, returns 422 `Invalid cursor`. The cursor is not signed: a re-encoded cursor with the right run scope is accepted, which is harmless because the query always filters by the requested run, so it can only move the start point within that run's own tasks; `limit` outside 1-500 returns 422. `GET /api/v1/runs/{id}` (the snapshot) is still unpaged. No mutation or scheduler operation is provided.
