Component registry

Component design contract

Each component has owned domain state, typed Python interfaces, published event schemas, optional external API routes, migrations, tests, and explicit permissions. In-process components use direct typed calls and durable events—not HTTP calls to themselves.

Catalog change · deterministic simulation

Demonstrates task progression, agent communication, review failure, correction, and a human approval gate. No real CLI, Git, or deployment actions occur.

Run invariants

A reviewer and validator must finish before a deployment approval can be requested. The demo does not contact STAGING.

✓ Isolated worktrees for editing attempts
✓ Independent review after correction
✓ Approval bound to candidate revision

Shared communication database

Agents exchange structured messages through an authenticated MCP gateway and the daemon's durable message service. Messages are not equivalent to successful task completion.
