# ADR 014: Optional fixed mock worker namespace launcher

Status: implemented as an opt-in module not wired to the daemon (`src/synapse/infrastructure/mock_sandbox.py`). The existing in-process mock engine remains unchanged. A separate, opt-in Linux launcher may run one fixed synthetic mock program in bubblewrap with new user, PID, mount, IPC, UTS and network namespaces, a private `/proc`, minimal `/dev`, private `/tmp`, read-only `/usr`, a single authorized managed worktree at `/work`, empty stdin, a minimal environment and no inherited extra descriptors. It creates a new process session and terminates the owned process group on cancellation/timeout. It fails closed if bubblewrap or required kernel features cannot be used; there is no unsandboxed fallback. No live provider CLI, SDK or subscription credential is used or mounted.

The trusted caller must validate that a directory is a managed worktree for the specific task, prevent other users or same-UID untrusted host processes from modifying its parent or contents, and provide a safe filesystem. The launcher verifies directory ownership and containment but does not yet implement a worktree registry, bind mounts by descriptor, enforce resource ceilings or protect against host same-UID processes, kernel vulnerabilities or malicious trusted code. User namespaces alone do not authenticate a human or authorize an approval. This is not a general agent sandbox or an isolation claim for subscription credentials. No network is available inside this mock sandbox. Enabling real providers requires a separately reviewed design for documented CLI profile access, network policy, process fencing, resource limits and gateway capabilities.
