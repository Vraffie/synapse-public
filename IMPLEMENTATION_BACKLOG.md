## Main priority: daily-use track (sole operator)

Set 2026-11-25. This track comes before any other open item. The goal is that the owner, as the only user, runs Synapse every day with a real Claude provider. Estimated 5 to 8 working days, a planning estimate and not a measured figure. Multi-user items (stronger approver identity, per-profile credential isolation, multi-user budgets) and the Codex adapter are out of scope for this track. The items are plain numbers on purpose: they are not milestone checkboxes and do not change the progress counts above.

0. Close out in-flight work: finish PR #44 (result cache store, migration renumbered to 0020, full suite green), triage PR #43 (ADR 026 design only, close if redundant), and check this backlog against the code so only real gaps remain.
1. First live run on a throwaway repository with a real Claude provider: create the run, work in the worktree, review, approve, commit. Record every failure. That list reorders steps 2 to 5. Done when one run completes with no manual database or process fixes. If the run exposes stream-json drift between Claude versions, the supported Claude version range and one stream-json fixture per verified version (M4-A) move to the front.
2. Real timeout and cancel runs: the child process group is killed, the worktree is left in a sane state, and the audit events are written. Done when a hung agent can be stopped from `agentctl` and from the desktop console and nothing is left orphaned.
3. Recovery and retention: resume for `recovering` runs and worktree retention cleanup. Done when a daemon killed mid-run resumes or lands in a clear state after restart, and old worktrees are cleaned up on a visible schedule.
4. Desktop client recovery and pagination: the console survives a daemon restart without a manual refresh and lists 500 or more runs without lag.
5. Per-profile concurrency limit. Only needed if agents run in parallel; skip it otherwise.
6. A short daily-use document: start, stop, backup and restore, and what to do after a crash.
